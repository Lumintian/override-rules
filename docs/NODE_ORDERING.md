# 节点排序与命名约定

## 一处配置，三个入口

地区和类别偏好统一放在 [`shared/preferences.ts`](../shared/preferences.ts)，供 `rename.js`、`sort.js`、`convert.js` 使用。来源前缀偏好只在多个来源合并后的 `sort.js` 与 `convert.js` 中生效；`rename.js` 一次只处理一个来源，不推断原节点名中的来源身份。不要再在 `src/constants.ts` 中复制排序权重。

```ts
export const countryWeights: Readonly<Record<string, number>> = {
    香港: 10,
    新加坡: 20,
    台湾: 30,
    日本: 40,
    韩国: 45,
    美国: 50,
    加拿大: 55,
    英国: 60,
    德国: 70,
    法国: 80,
};

// 默认是空对象：前缀按其在当前地区内第一次出现的顺序排列。
export const prefixWeights: Readonly<Record<string, number>> = {
    自建: 10,
    机场A: 20,
};
```

数值越小越靠前；未配置权重的已识别地区排在已配置地区之后。同权重地区仍各自成块，按首次出现顺序排列，不会被下一层的前缀或类别权重交叉打散。前缀同理。地区名称使用识别层的统一身份，例如马来、Malaysia、MY 均使用 `马来西亚` 这个权重键。

## 排序语义

```text
地区块 → name 前缀块 → 类别块 → 原始顺序
```

先构建块，再对整个块排序。排序器不使用国旗 Emoji、`localeCompare`、节点编号或排序过程中变化的数组索引作为优先级。

默认类别如下：

| 类别 | 判定 | 默认权重 |
| --- | --- | --- |
| `standard` | 无特殊线路标签，且未标倍率或倍率为 1 | 10 |
| `tagged` | 存在 IPLC、IEPL、家宽、自建、落地等特殊标签，且倍率不低于 1 或未标倍率 | 20 |
| `high` | 无上述特殊标签且倍率大于 1 | 30 |
| `low` | 明确倍率小于 1，包括有特殊标签的节点 | 90 |

倍率首先是计费标记，不是网络质量测量。`IPLC 0.2×` 分类为 `low`，不会因为带 IPLC 标签而越过低倍率分类。类别权重同样在共享偏好文件中调整。

**低倍率默认在“同地区、同前缀”内部沉底，而非整个地区或全订阅沉底。** 例如：

```text
机场A | 香港 01
机场A | 香港 0.2× 01
机场B | 香港 01
机场B | 香港 0.2× 01
机场A | 新加坡 01
```

同一类别不再按倍率数值二次排序。上游的法国 3×、法国 2× 都属于 `high` 时，仍保持 3×、2× 的出场顺序。

## 三个入口的职责

### rename：规范化、单来源排序、独立编号

一次 `rename.ts` 调用视为一个来源。脚本不会把原节点名中的 `|` 当作服务商边界，也不会调用 `splitPrefix()`；来源前缀只来自显式的 `name` 参数。

处理顺序固定为：

1. 读取 `in`、`out`、`name`、`blkey`、`chain` 和过滤参数。
2. 使用完整原节点名执行 `clear`、`nx`、`blnx` 等过滤，不预先拆分来源前缀。
3. 规范别名并识别地区、倍率和线路性质。
4. 根据 `bl`、`blgd`、`blkey` 生成最终显示标签。
5. 根据原名称及最终标签处理 `chain`，并处理 `blockquic`。
6. 使用国旗、显式 `name`、地区和标签生成不含编号的最终 `baseName`。
7. 按“地区 → 类别”进行单来源稳定排序；同一层级保持原始顺序。
8. 排序后根据完整 `baseName` 添加编号。
9. 最后改写本批节点之间的具体 `dialer-proxy` 引用。

`flag`、`out`、`bl` 等显示选项不会改变已经识别的地区和倍率。`name` 只负责输出前缀，不参与原名称解析。

计数器的键是完整的最终 `baseName`，不是地区：

```text
机场A | 香港 01
机场A | 香港 02
机场A | 香港 0.2× 01
机场A | 香港 IPLC 01
```

`one` 按同一个 baseName 的节点总数决定是否省略编号，不再用正则从最终字符串中删除 01。编号是本次输出的序号，不是跨订阅更新的永久节点 ID；上游节点增删或顺序改变，仍可能改变编号对应的真实节点。

`clear` 先清理明确的信息节点，再处理地区。没有 `nm` 时移除无法识别地区的节点；开启 `nm` 后放在全部已识别地区后面，并保持这些节点的原始顺序。`备用`、`测试`、`群岛` 不再单独作为删除依据。

如果 `dialer-proxy` 引用本批输入中的另一个具体节点，改名后会同步更新引用。外部策略组名称保持不变。引用目标被过滤，或目标原名称重复而无法确定身份时，会明确报错而不是输出断开的代理链。脚本不能更新这批输入以外的配置引用。

### sort：合并之后只排序

不同机场分别改名时，各自只能看到自己的节点。分别有序的数组直接拼接后，不一定满足全局地区聚类。因此，多个来源应当在 Sub-Store 合并后再运行 `sort.min.js`：

```text
机场A → rename（name=机场A |） ─┐
                              ├→ Sub-Store 合并 → sort → 导出节点
机场B → rename（name=机场B |） ─┘
```

`sort.ts` 不改名、不编号、不过滤节点，也不改协议、凭据或 dialer 字段。它从已经渲染的最终名字中读取地区、显式来源前缀和类别，再按“地区 → 来源前缀 → 类别”稳定排序。因此需要上游保留之后仍要使用的倍率和标签；已经从名称中删除的元数据，跨序列化后无法凭空恢复。

多个机场应使用不同的显式 `name` 前缀，避免分别生成完全相同的节点名称；`sort` 不会通过再次编号来掩盖重名。

### convert：排序合并集合，再生成候选列表

覆写入口先按“地区 → 来源前缀 → 类别”排序 `config.proxies`，再由它派生手动选择、枚举式地区组、额外地区组、前置候选和落地候选。`GLOBAL` 中的直接节点也使用显式有序名单。覆写只排序，不重新命名或编号。

如果合并后的集合会立即进入 `convert.min.js`，为了覆写结果的顺序正确，无须额外执行 `sort.min.js`；`sort.min.js` 主要用于直接导出 provider、查看合并节点，或其他不经过 convert 的流程。

## 前缀约定与解析边界

来源前缀只由各来源在 rename 阶段显式传入，例如 `name=机场A%20%7C`。`nf` 只决定该前缀与国旗的显示位置，不改变前缀身份。原节点名中的 `机场A | 香港` 在 rename 阶段只被视为普通完整文本，其中的 `|` 不具备来源分隔语义；未传 `name` 时不会自动保留 `机场A`。

`sort` 与 `convert` 面对的是 rename 生成的规范化最终名称，此时才使用 `splitPrefix()` 读取显式来源前缀。无竖线时，覆写会尝试把地区词之前的文本当作前缀；但来源名本身带地区词、多个地区同时出现、特殊分隔符等情况可能有歧义。需要确定性的多来源处理时，应在 rename 阶段显式传入带竖线的 `name`。

## 本次没有改变的边界

排序不等于测速策略。`url-test` 仍执行自身的节点选择算法；把低倍率排后，不代表自动测速组永远不会选它。需要禁止某类节点进入自动组，应另外设计成员过滤。

`regex=true` 的地区组仍使用动态 `include-all + filter`，实际运行时成员顺序和跨组匹配不由本排序器保证；预览器只是 JavaScript 近似模拟。需要精确候选顺序时，当前覆写使用默认的枚举模式。

本次没有把完整覆写迁移成 provider-only 配置，也没有部署或重启 OpenClash。`sort` 可以放在 provider 节点导出之前；但多个独立 provider 各自有序，不代表其下游合并后的候选列表也全局有序。需要上游保证全局地区聚类时，先合并再导出一个有序集合。

## 开发验证

```bash
npm ci
npm run typecheck
npm test
npm run artifacts
npm run preview
```

CI 在构建前运行回归测试。预览缓存追踪 `src/`、`shared/` 和 `scripts/substore/` 下的 TypeScript 文件；修改共享权重后无需重启预览服务。

源码分支不跟踪 `dist/` 产物。分支上的源码修改并不代表 `@dist` 已更新，需本地构建试用或等待维护者发布。
